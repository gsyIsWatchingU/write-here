## 文档加载慢：定位与后端四项优化（cd15eec，已部署并公网验收）

起因：小郭反馈「文档加载有时有点慢」。先量了加载链路再动手，没有靠猜。

**实测到的瓶颈（都在后端，前端未改）：**
- 编辑器共享 chunk `outlineNavigation` 835.8 KB，后端既没压缩也没缓存头（express.static 裸用，package.json 无 compression 依赖）。
- 列表类接口 `SELECT *`：工作台、社区、协作列表都把每篇文档正文全文回传（搜索接口早就用了 substr 200，列表没跟上）。
- SQLite 无 WAL，`docs.visibility` / `shares.docId` / `comments.docId` / `notifications(userId,isRead)` 都没有索引。

**改动：** compression（排除 /mcp/ 的 SSE）、assets 长缓存 + immutable / index.html no-cache、
列表接口改 200 字符预览、PRAGMA WAL + 4 个索引。
没动 836 KB 的拆包（manualChunks）和 y-indexeddb —— 前者要动构建配置有回归风险，
后者与 `provider.on('sync')` 后 `setContent` 的合并语义没定义，是风险最高的一项，留在「下一步」。

**实测数字：** 本地 835.8 KB → 278.3 KB；线上 `outlineNavigation-DJYAhHe4.js` 855,894 B → 284,986 B（-66.7%）。
后端测试 25 项全过（新增 `backend/test/staticDelivery.test.js` 4 项固化传输量与缓存头）。
