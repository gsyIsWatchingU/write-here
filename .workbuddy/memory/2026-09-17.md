## 文档末尾点击空白补行（`8135a71`）

**需求**：用户在编辑器里贴了一张截图 —— 正文只有一个空代码块，下面一大片空白，想在下面写正文却敲不出新行。
原话："如果最后一行是不方便通过换行键新建行的，那就允许鼠标点击下一行的开头来新建行"。

**根因**：已有 `blockGapInsertion.js` 只处理**块间空隙**（`clientY > 前一块 bottom && < 后一块 top`），文档末尾的空白返回 -1，回落到 ProseMirror 默认行为 → 光标落进最后一块内部。而代码块里的 Enter 只做块内换行（实测 `doc.textContent === "\n"`，不产生新块），所以末尾是代码块/列表/引用时确实"没有出口"。

**改动**（只动了 `frontend/src/utils/blockGapInsertion.js` + 其测试，两个页面共用同一个 handler，无需改 Vue）：

- 新增 `findTrailingInsertionIndex(blockRects, clientY)`：`clientY > 最后一块 bottom` 时返回 `blockRects.length`（= `doc.childCount`，即末尾插入索引）。**与块间判定分开**，不污染原函数语义（GPT 的建议，认同）。
- 新增 `shouldInsertTrailingParagraph(node)`：白名单 `TRAILING_ESCAPE_TYPES = {paragraph, heading}` 之外才补行。实测确认 TipTap 里标题和段落末尾按回车都直接得到普通段落（`heading,paragraph` / `paragraph,paragraph`），代码块和列表则不是。
- 主函数按 `trailingIndex >= 0` 分流：末尾分支只走类型白名单判断，**不再套用"相邻已有空文本块就不插"的规则** —— 这条规则会把空代码块拦掉（空代码块 `isTextblock && content.size === 0` 成立），而那正是用户截图里的场景。
- 防重复靠自然收敛：补行后末尾变成空段落 → 在 `TRAILING_ESCAPE_TYPES` 里 → 再点空白不会继续插。
