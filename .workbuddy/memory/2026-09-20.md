## 文档插图功能（feat 39aa79c，docs 335f5e5）

需求：为什么文档放不了图片；参照飞书做「图片默认居中 + 多图同行自适应」。

诊断（读源码确认，不是猜）：
- 图片被配成 `Image.configure({ inline: true })` 行内节点；
- `@tiptap/extension-image` 的 `parseHTML` 是 `img[src]:not([src^="data:"])`，base64 直接被丢弃；
- 后端根本没有上传接口，工具栏只有一个 `prompt('请输入图片链接地址：')`；
- 没有 `handlePaste` / `handleDrop`；`TextAlign` 只配了 heading/paragraph。

实现：
- 后端 `backend/imageUpload.js`：`POST /images/upload`，magic number 校验、10MB / 8000 万像素上限、
  sha256 内容寻址（`db/uploads/aa/bb/<sha>.<ext>`，不进 Git）、tmp+rename 原子写、同内容去重；
  `images` 表记录元数据。UPLOAD_DIR 可用环境变量覆盖。
- 前端 `DocImage`（扩展 Image，块级，align 走 `data-align`，默认 center）+ `ImageGroup` 容器节点
  （`content:'image*'`，不用 `image+`——Yjs 并发删除会瞬时空组，数量上限放业务层 6 张）。
- 三种插入入口：工具栏文件选择、粘贴、拖放；`frontend/src/utils/imageUpload.js` 保序并发 3，失败项隔离。
- 旧文档兼容：`legacyImageHtml.js` 的 `promoteInlineImages()` 在 Yjs sync 与 Markdown 导入时把
  `<p><img></p>` 提升为块级（整段只有图 → 单图/图片组；图文混排按原顺序拆开），幂等。
- 布局：**同行等高**的关键是把 `flex-basis` 设成 0、`flex-grow` ∝ 宽高比（`w_i ∝ r_i ⇒ h_i = W/Σr`），
  折行阈值由 `min-width:160px` 提供。第一版用 `flex: 1 1 160px` + clamp(0.4, 2.5) 实测两张高度 230 vs 304，
  改成 basis 0 + clamp(0.2, 5) 后实测 893×230 / 483×230，行宽 1384 = 容器宽。

验收：前端 93 项、后端 32 项、MCP check+5 项、生产构建、`node --check` 全过；
临时无头 Chrome（CDP 驱动真实 `input[type=file]` + 真后端 + 真 PNG）14 项全过，含
`setContent(getHTML())` 往返不丢图、旧行内图被提升。CI/CD 两轮（39aa79c、335f5e5）均部署成功，
`run/deployed-commit` 与本地一致，`deploy/verify-public.sh` 全绿（SQLite 11 表，新增 images）。
