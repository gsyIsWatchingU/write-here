## 修复「点击退出没反应」（e580d1f）

**问题**：工作台点右上角「退出」后画面完全不动（用户截图）。

**定位方法**：`run/logout-verify.mjs` + `src/harness/logoutHarness.js`
（临时无头 Chrome + CDP，真实 router 守卫 + 真实 Home.vue/Login.vue，
只把后端替换成可控假服务，但保留真实会话 cookie 语义）。跑五场景 19 项，
修复前前四场景失败：`path` 停在 `/` 而非 `/login`。

**两条独立根因**（都在源码里确认、都用浏览器复现过）：

1. `frontend/src/utils/api.js` 的 `clearUser` 用 `try { await fetch('/logout') } finally { ... }`
   —— `finally` **不吞异常**，`/logout` 失败时异常照旧抛给调用方；
   而四个页面的 `handleLogout` 都是 `await clearUser()` 之后才 `router.push`。
   后端不可达或卡住 → 永远走不到跳转 → 按钮"没反应"。
   另外 `clearUser` 在 `await` 之前没清 `localStorage`，
   正好留下"请求挂住则本地登录态也不清"的窗口。
2. `frontend/src/views/Login.vue` 的 `onMounted` 无条件调 `api.me()`，
   拿到用户就 `setUser + router.replace('/')`。若服务端会话还没失效
   （`/logout` 失败 / cookie 未及时清除），用户被立刻弹回首页 —— 视觉上同样是"没反应"。
   这条更符合截图（点击后画面完全不动）。

**改动**：
- `api.js`：`clearUser` 改成"先同步清 `localStorage`，再尝试通知服务端"，
  失败降级为 `console.warn`；新增 `sessionStorage` 退出标记
  `markLoggedOut` / `consumeLoggedOutFlag`。
- `Login.vue`：`onMounted` 先消费退出标记，主动退出进来时不自动跳回首页。
  用 `sessionStorage` 而非 `localStorage`（关标签页即失效），`setUser` 会清掉它防粘连。
- `components/TopNav.vue` 的 `handleLogout` 改为不 `await`（该文件由并行会话
  抽成公共导航组件，改动已含在 `1c6675a`）。
- 新增 `frontend/src/utils/logout.test.js` 5 项回归测试。

**验证**：CDP 五场景 19 项全绿；前端 109 项测试通过；
把 `clearUser` 临时回退成旧实现时新增测试有 2 项转红（确认测试非空转）；
生产构建通过；CI/CD 两个 job success；`run/deployed-commit` == HEAD；

## 教训 / 可复用

- **`finally` 不吞异常**。想"无论成败都做善后"要用 `catch`，用 `finally` 只会把异常继续抛出去，
  这次直接导致退出功能瘫痪。
- **凡是 `await` 一个网络请求之后才做 UI 状态切换的地方，都要问"请求挂了会怎样"**。
  登出、跳转这类本地状态变更应当同步做，网络通知可以后台化。
- **`@click` 后画面"没反应"有两种常见形态**：真的没进 handler（被拦截/未绑定），
  以及**进了 handler 又被自动跳转抵消**。排查时要在关键节点打点记日志，
  光看最终 URL 分不清这两种。
- 该仓库已有"临时无头 Chrome + CDP harness"的成熟模式（`run/pages-verify.mjs` 等），
  要复现前端交互 bug 直接沿用，别另起炉灶；用完把临时 harness 删掉再提交。
- 并行 session 会同时改同一仓库：本次编辑 `Home.vue` 时报 `EBUSY`，
  随后该文件被另一个 session 重构提交。**提交前务必重读文件确认当前实现**，
