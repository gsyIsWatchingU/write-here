## 编辑器快捷键语音转写（调用 GPU 的 ASR）

**需求**：在文档编辑器里加"按住快捷键说话 → 转写 → 插入光标处"，转写走后端调用 GPU 上的 ASR。

**关键发现（先说结论，下次省时间）**：

- GPU 服务器上跑着 tool-desk 的模型服务：`Qwen3-ASR-1.7B` 由 vLLM 托管在 `127.0.0.1:8001`，OpenAI 兼容 `POST /v1/audio/transcriptions`（multipart：`file` / `model` / `response_format`）。**8001 本身不校验 Authorization**，网关 `127.0.0.1:8100` 才需要 `MODEL_API_KEY`（在 `/workspace/projects/interview-model-service/.env`）。
- **write-here 后端与 ASR 在同一台 GPU 服务器**，所以后端直接用默认 `http://127.0.0.1:8001` 即可，不需要密钥、不需要走公网隧道。
- 服务器**没有 ffmpeg**，所以浏览器必须自己产出 ASR 能解的文件：用 WebAudio 采集 → 降采样到 16 kHz 单声道 → 自封 WAV（`PCM16`）。实测 vLLM 接受这种 WAV，2.5 秒音频约 117 ms 返回。
- 本机 PowerShell 的 `Add-Type`（System.Speech）与 `New-Object -ComObject`（SAPI）都被安全策略拦截，**没法用系统 TTS 造中文语音样本**，所以真人声识别只能由用户在线上自测。
- 本机做真实 GPU 链路验证的方法：`ssh -f -N -M -S /tmp/xxx-sock -o ExitOnForwardFailure=yes -L 18001:127.0.0.1:8001 mygpu`，隧道只在同一条 Bash 调用里存活（`ssh -f` 后台进程在命令结束后会被清掉，第二次调用就 ECONNREFUSED）。之后 `ASR_URL=http://127.0.0.1:18001` 就能在本地跑通整条后端链路。
- 注意：本机 `curl` 走代理环境变量，直连 localhost 端口可能返回 502；判断直连是否通要用 `node -e "fetch(...)"`。

## 快捷键改造：`Ctrl+Alt+M` → 双击 Ctrl（用户反馈三键太吃力）

**改动**（`048948a`）：

- `voiceInput.js`：删掉 `isVoiceShortcut`，改为 `isVoiceHoldShortcut`（单独的 `F2`，带任何修饰键都不算）和 `createShortcutDetector({ now })` —— 双击 Ctrl 的状态机。判定规则：
  - Ctrl 按下到抬起 ≤ 220ms 才算「轻点」，超过算「按住」（用它拖选、长按 Ctrl 的场景不误触）；
  - 两次轻点间隔 ≤ 420ms 触发；
  - **按下任何非 Ctrl 键时清空 `lastTapAt`**（否则「点一下 Ctrl → Ctrl+C 复制 → 再点 Ctrl」会被判成双击——这是写测试时发现的真实 bug）；
  - `event.repeat` 的 keydown 不刷新按下时间，否则长按 Ctrl 的重复事件会让累计时长看起来很短，长按被误判成轻点。
- `VoiceInputButton.vue`：`keydown` 处理 F2 按住（用 `holdShortcut` 标志挡 repeat），Ctrl 交给 detector；`keyup` 命中双击就 `toggle()`；`window blur` 时 `detector.reset()` 并收尾按住录音。
- 前端测试 55 项（新增 1 项、改写 1 项），构建产物含 `双击 Ctrl`/`ControlLeft`，旧的 `KeyM` 已消失。

**验证**：前端 55 项通过、`vite build` 通过、`node --check` 通过；`048948a` 已推送并部署，`deploy/verify-public.sh` 全绿，线上产物特征核对通过。

**没做的**：没有真实浏览器 e2e（编辑页要登录态 + 麦克风）。靠 11 项单测覆盖「按住 Ctrl / Ctrl+C 组合 / 重复 keydown 不误触」这几条边界。
